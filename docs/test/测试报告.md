# 拾光旅行一体化旅行平台（Lightmark）测试报告

[toc]

## 1 项目信息

### 1.1 项目概述

**系统名称**：拾光旅行（Lightmark）一站式出行旅游平台。

“拾光旅行”是一款集机票预订、酒店住宿、旅游度假、火车票购买、智能行程规划及社区分享于一体的综合型 Web 应用。系统采用响应式 Web 设计，前后端分离，一套代码适配 PC / 平板 / 手机。项目不仅涵盖传统在线旅游平台的核心电商交易链路，还创新性地引入了基于大语言模型的通用 AI 能力，如智能行程规划、评论情感分析、AI 游记生成与智能客服等，致力于为现代旅行者提供从“灵感获取-预订支付-行中服务-游后分享”的智能化全场景服务。

系统支持普通用户和管理员两类角色，提供产品查询、下单支付、退票改签、订单管理、AI 文案生成、智能行程建议、游记社区和后台运营管理等能力。主要功能模块包括：身份认证与权限控制、用户中心（出行人、积分、会员等级、我的订单）、机票预订、酒店预订、火车票预订、度假产品、智能行程与社区、AI 助手、管理后台。

### 1.2 技术栈

| 层次 | 技术选型 |
| --- | --- |
| 前端 | Vue 3 (Composition API)、TypeScript、Vite、Pinia、Vue Router 4、Element Plus |

| 外部依赖 | DeepSeek/OpenAI 兼容模型 API、12306 MCP 服务 |

### 1.3 测试目标与范围

本测试报告用于说明“拾光旅行 Lightmark”系统的测试范围、测试方法、测试环境、测试用例设计和测试执行结果。测试目标是验证系统在身份认证、用户中心、机票、酒店、火车票、度假产品、智能行程、社区、AI 助手和管理后台等核心业务中满足需求文档与详细设计说明书要求，并能够在典型用户流程下稳定运行。

本次整合报告包含三个测试层次：

- **单元测试**：使用 JUnit 5、Mockito、AssertJ，覆盖认证参数校验、会员等级规则、火车票与度假订单规则、积分与会员积分规则、AI 解析与降级规则、通用 CRUD 控制器、用户 ID 格式化工具等服务层规则、边界与异常路径。
- **集成/API 测试**：使用 SpringBootTest + MockMvc + H2（MODE=MYSQL）+ Java 17，通过 MockMvc 调用真实 Controller，覆盖度假、酒店、火车、机票、用户与权限、AI 六大目标模块，并验证数据库副作用。
- **端到端测试**：使用 Playwright Test 在公网环境（`https://lightmark.ortus.top`）以浏览器视角执行，覆盖健康检查、登录校验、未登录权限拦截、用户中心、机票、酒店、火车票、度假、社区和管理员入口。

### 6.2 风险

- **外部依赖风险**：12306 MCP 服务和大模型 API 的网络可用性会影响实时车次查询、AI 文案生成与智能助手等功能，系统需保持友好错误提示与本地降级逻辑（单元测试已覆盖 AI 降级路径）。
- **端到端用例依赖**：E2E-005～E2E-018 需要有效测试账号、初始化数据及可用的 12306/AI 外部服务，通过 `E2E_USER_TOKEN` 与 `E2E_ADMIN_TOKEN` 注入，未配置时会明确跳过，不能当作通过。
