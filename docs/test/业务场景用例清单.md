# Lightmark 业务场景（用例）清单

[toc]

## 1 引言

### 1.1 目的

课程任务书要求：第 1 天列出项目完整的业务场景（用例）清单并由教师/助教确认，确认后的清单即为最终验收范围。清单中的每个用例都要能运行，并能在需求、设计、代码、测试和追溯记录中一一对应；最终汇报从中选不少于 3 个代表性用例重点讲解。

### 1.2 用例定义

一个业务场景（用例）指：由一类用户或外部系统触发，为完成一个明确的业务目标，从开始到产生可验证结果的一段完整流程。一个用例可包含主成功流程、备选流程和异常流程（同一用例的不同路径）。单个页面、按钮、接口、数据库操作或流程中的一步，不单独算一个用例；登录、增删改查等若本身具有独立业务目标和复杂规则，可单列用例，但需写清触发者、目标和结果。

### 1.3 编号规则

按课程任务书建议的贯穿编号方式，每个用例在需求、设计、测试各环节使用同一序号：

| 前缀 | 含义 | 说明 |
| --- | --- | --- |
| `REQxx` | 需求编号 | 对应《软件需求规格说明书》5 章追溯表与《需求划分文档》功能点 |
| `UCxx` | 业务用例编号 | 本清单中的用例编号 |
| `SYS-SEQxx` | 系统级顺序图/状态图/活动图 | 需求阶段，每个用例 1 张（图见设计文档，实践期间补充） |
| `COMP-SEQxx` | 组件级顺序图/状态图/活动图 | 概要设计阶段，每个用例 1 张 |
| `OBJ-SEQxx` | 对象级顺序图/状态图/活动图 | 详细设计阶段，每个用例 1 张 |
| `UNIT-TCxx` | 单元测试编号 | 本清单引用现有单元测试报告中的实际编号（A/M/O/P/I/C/F 系列） |
| `INT-TCxx` | 集成/API 测试编号 | 引用现有集成测试报告中的实际编号（V/H/T/F/U/A 系列） |
| `E2E-TCxx` | 端到端测试编号 | 引用现有 E2E 测试报告中的实际编号（E2E-001 ~ E2E-018） |

> 说明：现有测试报告采用模块字母编号（如单元 `A000`、集成 `V000`、E2E `E2E-001`）。为与《测试报告》直接核对，追溯表中直接引用实际编号；如需按任务书规范映射为 `UNIT-TCxx / INT-TCxx / E2E-TCxx`，见附录 A。

### 1.4 实现状态与验收口径

- **已实现（含测试）**：功能已开发完成，且至少有一层自动化测试覆盖（单元/集成/E2E 之一），属于验收范围。
- **已实现（测试待补）**：功能已开发完成（API 文档标注【已实现】），但自动化测试覆盖不足，实践期间需补充测试后方计入验收范围。
- **未实现/待确认**：原项目中只有设想、尚未开发的内容，第 1 天向教师/助教说明后确认是否计入验收范围。

### 3.1 UC-01 用户注册

| 项目 | 内容 |
| --- | --- |
| 需求编号 | REQ01（M1-01 用户注册/登录/登出；R-USER-01） |
| 参与者 | 访客（未注册用户）、系统邮件验证码服务 |
| 触发条件 | 访客在注册页提交邮箱、昵称、密码、邮箱验证码与图形验证码 |
| 前置条件 | 图形验证码校验通过；邮箱域名受支持；邮箱未被注册；密码符合强度规则（8-20 位，含大小写字母和特殊字符） |
| 主成功流程 | 1. 访客获取图形验证码（`GET /api/auth/captcha`）；2. 访客填写邮箱并请求发送邮箱验证码（`POST /api/auth/verification/email/send`，先校验图形验证码）；3. 系统校验邮箱域名合法并发送验证码；4. 访客提交注册信息（`POST /api/auth/register`）；5. 系统校验验证码、昵称唯一性、密码强度；6. 系统创建用户（BCrypt 加密密码，邮箱/昵称规范化），返回用户信息 |
| 备选流程 | 手机号与国家区号作为资料保存（不参与登录）；昵称、邮箱、手机号已存在时返回 409 冲突（`A121`） |
| 异常流程 | 验证码缺失、弱密码、非法邮箱格式/不支持域名、昵称为空或超 30 字符、非法手机号/区号 → 均抛 `ApiException`（400） |
| 可验证结果 | 注册接口返回 `HTTP 200`、`code=0`、`data.email` 为注册邮箱；新用户可用账号密码登录 |
| 设计图编号 | SYS-SEQ01 / COMP-SEQ01 / OBJ-SEQ01 |
| 代码模块 | `AuthController`、`AuthService`、`AuthValidationService`、`UserRepositoryImpl` |
| 单元测试 | A000、A010、A020、A031、A040、A051、A060、A071、A080、A091、A100、A111、A121、A141 |
| 集成测试 | U000（注册→登录→当前用户链路） |
| E2E 测试 | E2E-002（登录入口校验，注册页必填提示） |
| 测试结果 | 全部通过 |
