## P2 代表性用例:火车票购买与 MCP 响应流(70s,重点页)

**追溯一句话**:需求 `R-TRAIN-02 火车票购买`(功能点 M5-03/M5-04)→ 设计(订单模块 + 微服务划分 §4 接口清单)→ 代码(product-service 查票 / order-service 下单)→ 测试(`TrainProductServiceTest`、`OrderServiceImplUnitTest`,演示实跑完整购买)。

**流程三段(建议配 1 张时序图,沿时间轴讲)**:

1. **查票——product-service ↔ 12306 MCP 会话**(讲师重点):
   - 前端站点联想来自 **station.csv(3100+ 站)**;
   - product-service 与 mcp-12306-server 建立 MCP 会话:`initialize` → 保存响应头 `Mcp-Session-Id` → 回发 `notifications/initialized`;
   - 此后每次查询是 `tools/call`,`method` 为 **`query-tickets` / `query-transfer`**(连字符命名),**每次携带 `Mcp-Session-Id` 头——无会话的请求会被 12306 服务端直接拒绝**,因此会话生命周期由服务内管理。
2. **下单——order-service 领域事务**:
   - 调 product `/internal/product/{id}` 校验在售与取价 → 调 user `/internal/user/{id}/travelers` 校验乘车人归属 → 本地事务落 `orders`;
   - 库存扣减;30 分钟未支付自动回补。
3. **失败处理**(呼应"调用失败怎么办"):
   - 依赖超时 3s + Resilience4j 重试 2 次/300ms + 熔断(10 窗口 5 次/10s 开)→ 前端"服务繁忙,请稍后再试";
   - 积分增减走 **outbox 表 + @Scheduled 5s 轮询**异步补发 →"下单成功,积分稍后到账";
   - 各服务独立 Deployment,不级联崩溃(4 分钟演示视频:停一个服务看隔离)。

**视觉**:时序图——浏览器 → Traefik → product-service → MCP;order-service 两条 internal 调用箭头;失败路径用红色虚线,指向"友好提示"。

## P3 微服务架构:划分依据 / 职责 / 表归属 / 模型到代码(50s)

**要点**
- 划分依据:**业务域 + 每张表唯一归属 + 跨服务只走接口、不跨库联表**(非按用例数机械拆分);消除单体"任意表 CRUD"设计;
- 四服务各一句话:user 认证信任根 / product 只读产品目录(含 MCP 查票)/ order 交易状态机 / content 内容+AI(DeepSeek,故障只降级不影响交易);
- 表归属(以火车票用例为例):`orders`/`payment_record` 属 order;乘车人 `traveler` 属 user,order 只能经 internal 接口校验——22 张表(20 迁移 + 2 MSA 新增)全量归属表见微服务划分文档 §5;
- 模型到代码:需求用例表(含 R-TRAIN-02)→ ER 与接口清单 → 各服务 Controller/Service/Repository 三层;接口清单即代码中真实映射,非文档杜撰;
- 会话:JWT 共享密钥签发、他服务只校验;验证码/登录的 HttpSession 收敛在 user-service + Traefik sticky cookie,多副本登录不漂移。

**视觉**:4 服务方块图(每块:职责 + 归属 schema + 端口);右侧小图"表→服务"归属;底部一行"需求→设计→代码→测试"追溯链。

## 问答弹药(3 分钟问答高频问题)

| 可能问题 | 答案要点 |
| --- | --- |
| MCP 会话为什么由 product-service 管? | 会话有状态(服务端会话),收敛在有状态能力最强的查询服务内,幂等重建:初始化失败会重建会话后重试 |
| 拆库后跨服务一致性? | 无分布式事务:本地事务 + internal 接口 + 超时重试熔断;写场景 outbox 异步补偿;库存 30 分钟回补兜底 |
| 火车票为什么不存数据库? | 12306 实时数据源,MCP server 提供实时查询;本地只维护站点字典 station.csv 做联想 |
| 性能差距 100 倍怎么解释? | 单副本 CPU limit 500m + Hikari 默认 10 连接 < 并发 30(排队型 p95);瓶颈在部署形态不在架构;4 副本线性补回,HPA 已验证;数据库非瓶颈(同库单体 6.9k rps) |
| 测试报告交哪个阶段? | 按老师答复:拆微服务后仍要测试,报告交第二阶段 |
| 为什么强调消除通用 CRUD? | 任意表读写使"表归属"无意义、接口无边界,是单体到微服务必须先消除的设计债 |
