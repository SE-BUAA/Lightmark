> 用途:服务器/本地部署与答辩前核对。每个勾选项给出命令与"通过"判据;

## A. 前置准备

- [ ] 服务器已初始化 k3s:`kubectl get nodes` 输出 Ready
- [ ] 服务器已安装 mysql 客户端与 curl:`command -v mysql mysqldump curl`
- [ ] 压测工具已装(如需实验):`sudo apt-get install -y apache2-utils && command -v ab`
- [ ] 根目录 `.env` 齐全(见 README §3.2);`JWT_SECRET` ≥32 字节
- [ ] GitHub Secrets/Variables 已配: SERVER_HOST / SERVER_USER / SERVER_SSH_KEY /
      SERVER_ENV_BASE64 / INGRESS_HOST / MSA_INGRESS_HOST / CERT_DIR / DEPLOY_DIR
- [ ] 测试账号可登录:`admin@lightmark.com / Qwe123456!`(管理后台)

## B. 单体版部署核对(develop / lightmark.ortus.top)

### B1 本地源码

- [ ] `cd backend && ./mvnw spring-boot:run` 启动无异常,`curl http://127.0.0.1:8080/api/health` 含 UP
- [ ] `cd frontend && npm run serve`,浏览器开 `http://127.0.0.1:8081` 首页可开

### B2 本地/单机 Docker

- [ ] `docker compose -f docker-compose.yml -f docker-compose.mysql.yml up -d --build` 全部 healthy
- [ ] `curl -I http://127.0.0.1/api/auth/captcha` 返回 200 与 image/png

### B3 服务器(CI 或手动)

- [ ] push `develop` 后 Actions 五个阶段全绿(测试→前端→镜像→部署→健康检查)
- [ ] `kubectl get deploy -n lightmark | grep -E 'backend|frontend'` 均 1/1 Ready
- [ ] `kubectl get deploy lightmark-backend -n lightmark` 副本 ≥1(**HPA 演示后记得恢复**)
- [ ] 公网 `https://lightmark.ortus.top/api/health` 返回 UP(经 Cloudflare)
- [ ] 服务器部署历史有记录:`grep '|deploy|' ~/lightmark/deploy-history.log | tail`

## C. 微服务版部署核对(msa-develop / msa.lightmark.ortus.top)

### C1 本地一键

- [ ] `bash msa/run-local.sh`(或 ps1)结束输出"本地 MSA 全部就绪"
- [ ] `docker ps | grep lightmark-msa` 6 个容器(mcp-12306 状态 healthy)
- [ ] `http://127.0.0.1:8081~8084/api/health` 全部 200;`http://127.0.0.1:9000/health` 200
- [ ] `http://127.0.0.1:8080/` 首页含 Vue 挂载点;验证码可显示
- [ ] 各服务 Flyway 无报错:`docker logs lightmark-msa-user 2>&1 | grep -i flyway | tail`

### C2 服务器 CI 部署

- [ ] push `msa-develop` 后 Actions 全绿(测试→4 服务+前端镜像→deploy→健康检查)
- [ ] `kubectl get deploy -n lightmark | grep -E 'user|product|order|content|msa-frontend'` 全部 1/1
- [ ] 拆分已执行:输出含 `[OK] split export completed`;`lightmark_user/product/order/content` 存在且有数据
- [ ] 粘滞路由在:`kubectl get ingressroute -n lightmark` 含 msa-user-auth-sticky(及 -tls)
- [ ] 会话粘滞有效(≥2 副本时):两段式 curl 六轮均返回 `captcha invalid`(见 FAQ 7)

### C3 入口与数据(答辩必查)

- [ ] DNS:`dig msa.lightmark.ortus.top` 指向服务器 IP(灰云直连)
- [ ] `http://msa.lightmark.ortus.top/` 200 且含 `id="app"`
- [ ] 验证码:`curl -s -o /dev/null -w '%{http_code} %{content_type}' http://msa.lightmark.ortus.top/api/auth/captcha` → `200 image/png`
- [ ] 机票搜索:`/api/flights/search?departureCity=BJS&arrivalCity=SHA&page=1&size=5` total>0(机场码 PEK 也应命中)
- [ ] 酒店:`/api/hotel/list?keyword=上海&page=1&size=5` total>0 且含 `records`
- [ ] 火车:`POST /api/trains/search {startStation:"北京",endStation:"上海",date:"<近3日>"}` 返回车次;
      站点下拉:`GET /api/trains/options` 含 startStations(数百以上)
- [ ] MCP:`curl http://127.0.0.1:9000/health`(服务器)200;`docker ps | grep 9000` 无旧容器冲突
- [ ] AI:content-service 日志无 "AI 服务暂时不可用" 降级(Secret 含 DEEPSEEK_API_KEY)

## 常用排查命令

```bash
# 服务状态与日志
kubectl get deploy,pod,hpa -n lightmark -o wide
kubectl logs deploy/user-service -n lightmark --tail=100
docker logs lightmark-msa-user --tail=100          # 本地

# 分库数据核对(以拆分脚本同源为准)
mysql -h <host> -N -e "SELECT COUNT(*) FROM lightmark_user.user;
SELECT COUNT(*) FROM lightmark_product.product;"

# 会话粘滞验证(2 副本时六轮均应为 captcha invalid)
for i in $(seq 1 6); do
  curl -s -c /tmp/c.txt -o /dev/null http://msa.lightmark.ortus.top/api/auth/captcha
  curl -s -b /tmp/c.txt -X POST -H 'Content-Type: application/json' \
    -d '{"account":"admin@lightmark.com","password":"Qwe123456!","captchaCode":"XXXX","privacyAccepted":true}' \
    http://msa.lightmark.ortus.top/api/auth/login; echo
done
```
