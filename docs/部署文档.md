# 部署文档

## 1 引言

### 1.1 编写目的

本文档旨在指导项目团队在生产环境中部署“拾光旅行（Lightmark）”一站式出行旅游平台，确保系统能够稳定运行并顺利通过验收。

### 1.2 定义

- API：应用程序编程接口
- DNS：域名系统
- CDN：内容分发网络
- Docker：容器化平台

### 1.3 预期读者

本文档的预期读者包括开发团队、系统管理员以及课程评审教师/助教。

### 1.4 参考资料

- 《拾光旅行软件需求规格说明书》
- 《拾光旅行软件概要设计说明书》
- 《拾光旅行软件详细设计说明书》

## 2 系统部署要求

### 2.1 硬件要求

- 服务器：4核CPU，24GB内存，200GB SSD存储（实际使用Oracle Cloud ARM实例）
- 操作系统：Ubuntu 22.04 LTS
- 数据库：MySQL 8.0（容器化运行）
- 缓存：Redis 7.0（容器化运行）
- 网络：公网IP，至少100Mbps带宽

### 2.2 软件要求

- 操作系统：Ubuntu 22.04 LTS（宿主机）
- 容器运行时：Docker 24.0 + Docker Compose 2.20
- Web服务器：Nginx（容器化运行，负责反向代理与静态资源服务）
- 后端运行环境：OpenJDK 17（容器内）
- 前端构建环境：Node.js 18（本地或CI环境）
- 数据库：MySQL 8.0
- 缓存：Redis 7.0
- 域名与CDN：Cloudflare（DNS解析、SSL证书、CDN加速）

## 3 系统部署方案

### 3.1 服务器资源

**应用服务器（兼顾Web、后端、数据库、缓存）：**

- 云服务商：Oracle Cloud
- 实例类型：Ampere A1（ARM架构）
- 规格：4核CPU / 24GB内存 / 200GB磁盘
- 操作系统：Ubuntu 22.04 LTS
- 域名：lightmark.ortus.top

> 说明：所有服务（Nginx、后端Spring Boot、MySQL、Redis）均以Docker容器形式运行在同一台服务器上，通过内部网络通信。

### 3.2 软件资源

| 软件                | 版本       | 用途                        |
| :------------------ | :--------- | :-------------------------- |
| Docker              | 24.0.x     | 容器运行时                  |
| Docker Compose      | 2.20.x     | 多容器编排                  |
| Nginx（容器）       | alpine     | 反向代理 + 前端静态资源服务 |
| Spring Boot（容器） | 3.5.13     | 后端REST API                |
| MySQL（容器）       | 8.0        | 关系型数据库                |
| Redis（容器）       | 7.0-alpine | 缓存与会话存储              |
| Cloudflare          | -          | DNS、CDN、SSL证书           |

### 3.3 应用服务器部署概述

#### 3.3.1 部署流程

**总体步骤：**

1. **服务器初始化**：更新Ubuntu系统，安装Docker及Docker Compose。
2. **准备项目文件**：将代码仓库克隆到 `/opt/lightmark`，包含前端构建产物、后端jar包、Dockerfile、docker-compose.yml以及Nginx配置文件。
3. **数据库初始化**：使用Docker Compose启动MySQL容器，执行建表脚本并导入演示数据。
4. **后端服务部署**：构建Spring Boot镜像，启动容器，连接MySQL和Redis。
5. **前端静态资源部署**：将构建好的 `dist` 目录挂载到Nginx容器，配置反向代理规则。
6. **Nginx配置**：设置80端口监听，将 `/api/` 请求代理至后端，前端路由使用 `try_files` 支持history模式。
7. **Cloudflare配置**：添加DNS A记录指向服务器公网IP，开启代理（橙色云朵）；配置SSL/TLS为Flexible模式；强制HTTPS跳转。
8. **启动所有容器**：通过 `docker-compose up -d` 一键启动。
9. **验证部署**：访问 `https://lightmark.ortus.top` 测试核心功能。

#### 3.3.2 系统软件

- Web服务器：Nginx（官方alpine镜像）
- 反向代理：由Nginx容器统一处理前端静态资源与后端API转发

#### 3.3.3 系统软件配置要点

- Nginx容器监听宿主机的80端口，并将 `/` 指向前端静态文件目录，将 `/api/` 代理到后端容器（内部端口8080）。
- 启用gzip压缩，优化前端资源传输。
- 设置 `proxy_set_header` 传递真实客户端IP（配合Cloudflare）。

### 3.4 MySQL数据库服务器部署

#### 3.4.1 部署描述

由于采用容器化部署，MySQL与后端应用运行在同一台服务器上，但通过Docker网络隔离。

**主要步骤：**

1. 在 `docker-compose.yml` 中定义MySQL 8.0服务，挂载数据卷实现持久化。
2. 设置环境变量：root密码、数据库名、应用用户名及密码。
3. 将初始化SQL脚本（建表+演示数据）挂载到 `/docker-entrypoint-initdb.d`，容器首次启动时自动执行。
4. 将MySQL端口绑定到宿主机 `127.0.0.1:3306`，仅允许本地访问，不暴露到公网。

#### 3.4.2 系统软件

- 数据库引擎：MySQL 8.0
- 客户端工具：DBeaver / Navicat（可选，用于运维）

#### 3.4.3 系统软件配置

- 数据库名：`lightmark`
- 应用用户名：`lightmark_app`（仅拥有 `SELECT, INSERT, UPDATE, DELETE` 权限）
- 字符集：`utf8mb4`，排序规则：`utf8mb4_unicode_ci`
- 时区：`+08:00`（Asia/Shanghai）

### 3.5 Cloudflare配置概述

- **DNS记录**：添加A记录 `lightmark` 指向服务器公网IP，开启代理（橙色云朵）。
- **SSL/TLS**：加密模式选择 **Flexible**（边缘到源站为HTTP），并开启 **Always Use HTTPS**。
- **缓存规则**：针对 `/api/*` 路径设置“绕过缓存”，避免API响应被缓存。
- **防火墙**：可根据需要配置速率限制或仅允许Cloudflare IP访问源站（可选）。

## 3.6 CI/CD 持续交付（GitHub Actions + Kubernetes）

### 3.6.1 流水线设计

向 `develop` 分支 push 后，GitHub Actions 自动执行，阶段严格串行（任何一步失败，后续部署立即停止，本次 Run 记录为失败并保留）：

| 阶段 | 内容 | 门禁 |
| --- | --- | --- |
| ① 后端测试 | 取代码 → Maven 安装依赖 → 单元测试 + 集成测试（H2） | — |
| ② 前端编译 | 取代码 → npm 安装依赖 → 编译 | — |
| ③ 制作镜像 | 构建并推送后端 / 前端镜像到 GHCR，标签 `1.0.<run_number>` + `sha-<commit>` | ① ② 通过 |
| ④ 部署 K8s | SSH 上传部署文件 → 服务器 `deploy-k8s.sh`：生成 Secret/ConfigMap、`kubectl apply`、等待 rollout | ③ 通过 |
| ⑤ 健康检查 | 后端 `/api/health`（UP）+ 前端首页（200） | ④ 通过 |

### 3.6.2 镜像版本管理

- 镜像不使用 `latest` 作为部署依据，统一使用版本号 `1.0.<run_number>`（GitHub 每次运行自增）与提交哈希标签 `sha-<commit>`；
- 版本号贯穿「构建 → 推送 → 部署 → 回滚」全链路，`deploy-k8s.sh` 将版本号渲染进 Deployment 镜像引用。

### 3.6.3 部署记录与回滚

- GitHub Actions 保留每次 push 的 Run 历史、日志与测试报告 Artifact；
- 服务器 `deploy-history.log` 追加记录每次部署的 时间 / commit / 版本号 / 镜像 / 结果（STARTED、SUCCESS、FAILED、ROLLED_BACK）；
- 部署或健康检查失败时自动 `kubectl set image` 回滚到上一次成功版本，并写入 ROLLED_BACK 记录。

### 3.6.4 Kubernetes 部署文件（deploy/k8s/）

- `namespace.yaml`：`lightmark` 命名空间；
- `mysql.yaml`：MySQL 8.0.43 官方镜像 + PVC（10Gi）+ Service `mysql`；初始化 SQL（`database/lightmark.sql`）以 ConfigMap 形式挂载 `/docker-entrypoint-initdb.d`，数据卷为空时自动建表并导入测试数据；
- `backend.yaml`：Spring Boot Deployment + Service `backend`，就绪/存活探针 `/api/health`，环境变量来自 Secret（服务器 `.env` 生成）；
- `frontend.yaml`：Nginx 前端 Deployment + Service `frontend`；
- `ingress.yaml`：Traefik Ingress，`/api/*` → `backend:8080`，`/*` → `frontend:80`，TLS 使用服务器证书（无证书自动生成自签名）。

## 4 注意事项

1. **安全组/防火墙配置**（Oracle Cloud控制台）：
   - 入站规则：允许源 `0.0.0.0/0` 的 TCP 80（HTTP）和 443（HTTPS）端口。
   - 禁止 3306、6379、8080 等内部端口对公网开放。
2. **数据持久化**：
   - MySQL和Redis的数据卷必须正确挂载，防止容器重启导致数据丢失。
   - 定期备份数据库（可使用 `mysqldump` 脚本）。
3. **资源限制**：
   - 后端JVM堆内存限制为 `-Xmx512m`，避免内存溢出。
   - 可通过Docker Compose为各容器设置CPU/内存上限。
4. **域名与HTTPS**：
   - 使用Cloudflare的Flexible SSL时，源站Nginx无需配置证书，但浏览器到Cloudflare边缘是加密的，满足演示要求。
   - 若需更高级别安全，可升级为Full模式并在Nginx中配置自签名证书。
5. **日志与监控**：
   - 容器日志可通过 `docker logs` 查看，建议挂载日志目录到宿主机以便持久化。
   - 可使用 `docker stats` 监控资源占用。
